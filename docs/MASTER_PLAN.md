# RuleReaper — Master plan
Status: P0 prototype; future work is not shipped. Product goal: profitable, viral global browser game. No live LLM, no paid infrastructure without owner approval. Revenue is not guaranteed.

## Product and rules v1
One sentence: escape a puzzle, ban one move pattern you used, and challenge the next player. A 5×5 maze with a fixed start, exit and walls per board; orthogonal moves U/D/L/R, no revisits, no wraparound. A restriction is an ordered pair of consecutive moves, excluding reversals (already illegal). After winning, choose a previously unbanned pair in your valid path. A solver must demonstrate a legal alternative on the identical board with the added ban. Every child invalidates its parent's submitted solution; restrictions accumulate. Max eight bans; if no legal reap remains, the chain is terminal; celebrate and offer a fresh chain. No silent rule removal. Difficulty is not necessarily monotonic in human perception. A generation is a ban count, not a win count. Branches instead of one shared mutable global level prevent contention and give every winner ownership. Immutable ruleset version and board.

## Viral loop and retention
First session: one-click play without login, simple visual tutorial, win in under 60 seconds as a design target, pick a rule, share challenge, friend opens directly into that state. A shared link must carry the specific challenge; no generic landing screen. Share text: "I escaped with X moves. I banned RR. Can you beat my new rule?" Show generation, bans and solve results; never fabricate social statistics. Production links use immutable challenge IDs and attractive Open Graph previews. Add copy fallback, share attribution via opaque referral ID, consent-aware analytics, daily puzzle, weekly community chains, personal challenge lineage, optional notifications with consent. Revisit reasons: daily seed, real friend activity, new branches. No forced invitations, fake urgency, streak penalties or spam. Start with short video clips and communities that welcome puzzle sharing; no paid acquisition until retention and contribution margin are proven. Test a simple maze versus an obstacle variant only after core loop validation. Global English first; localization after evidence.

## Business model and metrics
Stage 0 no ads: test enjoyment first. Stage 1 optional contextual/rewarded ads after completed game only (never interrupt moves); paid cosmetic trails, themes, ad-free pass, private rooms or curated puzzle packs. No pay-to-win, gambling, cash prizes or paid gameplay advantages. Test willingness to pay before implementing checkout. Hypotheses: S$2.99 theme pack, S$4.99 ad-free unlock; pricing not approved. Sponsorship after real audience; review ad network eligibility, privacy, age suitability, tax, refunds and platform fees before launch. If web ad economics are poor, test portal distribution subject to exclusivity and revenue-share terms.
Track events: landing, start, first_move, finish, reap_selected, share_clicked, referred_visit, referred_start, return, purchase (later). Deduplicate, avoid collecting text or unnecessary identifiers. D1/D7 cohort retention by first play; completion by starts; share rate by winners; referral conversion by referred visits; viral K = referred new players per active player per defined generation (deduplicated). Measure p50/p95 time to first win and solver latency. Revenue per DAU, ad fill/eCPM, conversion, payment fees, variable infra per DAU and contribution margin. Initial internal go/no-go hypotheses with >=100 distinct testers: >=50% complete tutorial, >=15% winners share, >=20% D1 retention, >=8% D7; use confidence intervals and qualitative feedback, not rigid claims of industry benchmarks. Aim K >=1 eventually; if lower, improve share conversion or use low-cost distribution. Never buy traffic if measured LTV contribution < CAC.
Illustration only: 10,000 DAU × 2 monetized impressions × S$3 net eCPM × 30 / 1000 = S$1,800/mo gross ads. At 20% fill, S$360 if impressions represent opportunities instead. Subtract infra, acquisition, fees, taxes and labor. Set first-stage cash ceiling S$50/month, approve any increase; no guaranteed free tiers. Track spend and cap requests. No AI cost per play.

## Technology
P0: semantic HTML/CSS, modern ES modules, Node built-in tests. This DOM grid needs no Phaser, React, or GPU. Zero build/dependencies and static CDN hosting keep payload and operational cost low. Pure engine with deterministic rules shared later by server. Node LTS, pinned dependencies and lockfile when introduced. P1 recommended: TypeScript migration only if needed, Vite/React for larger UI, Cloudflare Pages static frontend, Cloudflare Workers stateless API, Supabase PostgreSQL/Auth managed persistence; verify provider pricing, regional data/privacy and limits before setup. No Redis, WebSockets, always-on server, or inference API. Web Worker if solver blocks UI; no P0 network dependency. The GitHub Pages demo deploys versioned static assets from main. Legacy v1 links open the original grid. New v2 links specify the maze and its rules.

## Engine and contracts
Board cell indices 0..24. Rules unique sorted strings from legal pair set. Path at most 25 integer cells, starts at 0, ends at 24 for a win, no early goal, visits each cell once. Each move and pair checked. Solver exact bounded DFS with cell, previous direction and visited bitmask, returns solved with witness, unsolvable only on complete exhaustion, unknown if budget exhausted; fail closed on unknown. A candidate must appear in the submitted path and preserve witness. Validate witnesses independently. No trust in client state. Canonical serialization and ruleset version; cap input size. Tests: adjacency, wrap, revisits, forbidden pairs, wrong endpoints, alternate witness, cap, malformed rules and unknown budget.

## P1 backend design
Tables: boards(id, version, layout, hash unique); challenges(id, board_id FK, parent_id FK nullable, canonical rules, depth, created_by, created_at, rule_hash, UNIQUE(parent_id, rule_hash)); attempts(id, challenge_id FK, player_id, successful_path, idempotency_key, created_at, UNIQUE(player_id,idempotency_key)); reaps(attempt_id UNIQUE, child_id FK, rule); daily_seeds(day UTC PK, challenge_id); profiles(auth_id PK, alias optional). Root unique per seed; index parent, date, challenge. Preserve parent board/version, exact one added rule and depth in transaction; immutable nodes, unique child upsert. One accepted reap per attempt; idempotent retries and concurrent branches. Store only necessary successful paths, not every move. No raw IP in gameplay database. Public safe challenge reads, authenticated anonymous or registered writes; RLS deny direct unsafe writes; service credentials server-side.
API: GET /v1/challenges/:id; GET /v1/daily; GET /v1/challenges/:id/children (cursor); POST /v1/challenges/:id/attempts {path,idempotencyKey}; POST /v1/attempts/:id/reap {rule,idempotencyKey}. 400 malformed, 401 auth, 404 missing, 409 conflict, 422 invalid, 429 rate limit, 503 solver budget exceeded. Server recomputes validation and witness; never accept browser score. Bound request body, path, rules and solver steps; enforce session/IP limits, CORS, CSP, auth issuer/audience, prepared statements, cost caps. Test transaction races, ownership, retry, unauthorized access and forged paths. Staging migrations, backup/restore and rollback before launch.

## Agent work breakdown and acceptance gates
P0 engine agent: src/engine.mjs, tests/engine.test.mjs; preserve exported contracts, deterministic replay and fail-closed proof. UI agent: index.html, src/app.mjs, style.css; mobile responsive, keyboard, undo/reset, status, share link, terminal flow. QA agent: review engine independently, browser E2E on Android/iOS/desktop, accessibility, broken share links, low-end device performance. P0 exit: tests pass and real browser verification; no network calls, no global stats claimed.
P1 backend agent: migrations/, api/, server tests; auth, transactional branch creation, idempotency and quotas. P1 UX agent: server challenge adapter, immutable share ID and preview, daily seed, history, real aggregate stats. P1 exit: staging security/integration checks, p95 API target <300ms excluding explicitly bounded solver, load tests at 10/100/1000 concurrent simulated clients with no fake claims, measured cost. 
P2 growth agent: analytics event contract, dashboard, A/B plan, invite attribution, daily challenge, feedback. Test with 100 consenting real players; report retention, completion, shares, referral conversion and qualitative feedback. Do not invent data. P2 gate: evidence of core fun before ads.
P3 monetization agent: policy review, pricing experiments, ad placements, cosmetic catalog, checkout sandbox/webhook signature verification/idempotency/refunds; no actual payments until approved. P3 gate: no gameplay advantage, measured positive variable contribution and acceptable retention impact.
P4 scaling agent: cache public reads, indexes, pagination, WAF/rate limits, observability, backup drills; optimize based on measured bottlenecks; do not expose owner GPUs.
Product owner reviews milestones. P0 ~3 days, P1 ~1–2 weeks, P2 at least 7 days of observation, P3/P4 conditional; estimates only, not delivery promises.

## Testing, release and cost controls
Node tests locally and CI; browser smoke tests before demo; later Playwright on mobile viewport and keyboard. Target 44px touch cells, visible focus, text labels, reduced motion, no color-only state. Track JS errors, solver budget exhaustion, request latency, DB load, spend and uptime. Rate limits, abuse protection, bounded inputs. Deploy versioned assets and staging first; rollback frontend, backward-compatible DB migrations. No secrets or PII in public repo. No license selected; owner decides before accepting outside contributions. No claims of trademark clearance or global originality.

## Current exclusions
No real accounts, shared global database, leaderboards, ads, payments, analytics tracking, production hosting or AI inference in P0. Local URLs encode the maze and rules. Authoritative provenance remains a P1 feature. Never advertise P0 as globally connected.
